# Права участников и комментарии — 0.6.5

Установите 0.6.5 на компьютеры всех участников. Для постоянных VPS-сессий обновите также сервер из архива этого релиза. P2P использует протокол v8 и не подключается к старым клиентам.

## Настройка прав

Хост P2P выбирает **Права участников** в панели сессии или запускает **Pair Notebook: Права участников** через палитру команд. Владелец постоянной VPS-сессии открывает тот же пункт в **Manage Persistent VPS Session**. Выберите участника, затем настройте:

- **Все файлы / Только выбранные файлы и папки / Только чтение.** `src/main.py` разрешает конкретный файл, `src/` — папку со всеми вложенными файлами. Переименование требует разрешения на исходный и новый путь. Удаление или перенос папки требует прав на каждый затронутый файл. Новые файлы внутри разрешённой папки тоже разрешены.
- **Запуск Python и управление вычислениями.** Запрет проверяется хостом/сервером, включая прямые запросы и запуск ранее поставленного в очередь задания. Уже запущенное вычисление автоматически не останавливается. Для остановки используйте существующую команду с подтверждением.
- **Комментарии к строкам.** Разрешает создавать и закрывать собственные комментарии. Хост/владелец также может закрыть чужой комментарий.
- **Общая консоль P2P: Нет доступа / Только просмотр / Просмотр и ввод команд.** По умолчанию гости только смотрят. Доступ проверяется перед отправкой истории и вывода, при приёме команды и после подготовки рабочего каталога. Ctrl+C общей оболочки подтверждает хост. Существующий VPS-сервис не предоставляет общую оболочку ОС; на VPS управление кодом относится к запуску ноутбуков.

Настройка применяется после завершения диалогов. Отмена любого шага сохраняет предыдущие права. Хост/владелец всегда сохраняет полный доступ; роль VPS-администратора сама по себе не даёт менять эти права. Владелец может изменить права конкретного участника, первоначально пришедшего по приглашению «только чтение»; срок и отзыв приглашения продолжат действовать.

Права сохраняются при переподключении, перезапуске VPS и передаче P2P-хоста. Новые участники сохраняют прежние значения по умолчанию: редактирование всех общих файлов, Python и комментарии разрешены; консоль P2P — только просмотр.

Ограничение файлов относится к совместному редактору и API синхронизации. Python и команды оболочки могут менять файлы средствами ОС и имеют более широкие возможности. Если участнику нужно разрешить только выбранные файлы, отключите запуск кода и ввод в консоль. При переходе с полного доступа на ограниченный редактор не отмечает Python по умолчанию. Это управление возможностями сессии, а не изоляция произвольного исполняемого кода по файловым ACL.

## Комментарии через ПКМ

1. Откройте обычный файл или ячейку Jupyter в подключённом проекте.
2. Выделите одну или несколько строк. Без выделения используется текущая строка.
3. Нажмите ПКМ → **Pair Notebook: Комментарий к строкам** и введите текст.
4. Строки получают подсветку, а справа от первой строки появляется приподнятая метка с именем автора и началом комментария. Наведение показывает полный текст.
5. Чтобы закрыть комментарий, вызовите ПКМ → **Pair Notebook: Закрыть комментарий** и выберите его в списке.

Цвет совпадает с цветом курсора автора. По умолчанию он стабильно выбирается по идентификатору участника; **pairNotebook.cursorColor** позволяет задать свой цвет `#RRGGBB`. Комментарии привязаны к тексту через Yjs-якоря, поэтому вставка строк выше сдвигает их вместе с текстом. Комментарий к удалённой ячейке или заменённой реплике не рисуется на другой ячейке/файле.

VPS сохраняет комментарии между отключениями и перезапусками. Комментарии к Private-файлам доступны владельцу; после изменения видимости участники получают обновление. Лимиты сессии: 256 открытых комментариев, 4000 символов на комментарий. В P2P комментарии хранятся в метаданных сессии, а не добавляются в исходный код.

## Проверка

Автоматические тесты проверяют HTTP- и P2P-границы прав, запрет самостоятельного повышения прав, переименование/удаление поддеревьев, CRDT-обновления, сохранение политики на диске, отзыв консольных прав до запуска, приватность комментариев и привязку после вставки строк. Тест взаимодействия редактора проверяет команды, границы выделения, цвет и смещение метки; нативный E2E-набор проверяет регистрацию новых команд в VS Code. Конкретный внешний вид зависит от темы и шрифта редактора.
