## Что выполнялось

Настоящие production broker CLI, polling Python agent, detached runner и CPU
training process работали на Linux loopback. Monitor имел независимую ОС-сессию
и PPID 1 после завершения инициирующей оболочки. Открытый чат не поддерживал
жизнь вычисления. По завершении алгоритмического числа шагов monitor получил
терминальное состояние и выполнил предусмотренную очистку сервисов; после
перезапуска среды старые PID отсутствуют.

Workload — явно обозначенная synthetic инфраструктурная fixture: stdlib
logistic baseline, 14 400 настроенных шагов, минимум одна секунда на шаг,
20 обновлений на шаг. Условие завершения — число шагов, а не wall-clock limit.
CPU model и optimizer velocity загружались из атомарно опубликованных
checkpoints и сравнивались с сохранёнными состояниями. Это не проверка
научного преимущества fraud-модели и не доказательство эквивалентности resume
trajectory; последняя проверяется отдельным reference-pipeline тестом.

Данные владельца существовали физически в owner workspace. Agent проверил
version/files/size/SHA-256 manifest и подготовил изолированную копию для run.
`PAIR_NOTEBOOK_WORKSPACE` у training указывал на эту копию. Dataset identity и
hash самого файла сохранены в evidence отдельно: manifest hash и file hash
обозначают разные сущности.
