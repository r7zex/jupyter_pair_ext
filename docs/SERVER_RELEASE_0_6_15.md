# Pair Notebook 0.6.15 verification

Temporary self-host workspaces now record an initial file baseline. Normal cleanup removes the working copy and preserves changed files, dirty editor snapshots and journals in compressed recovery archives. Markerless legacy copies have no trustworthy baseline, so their full contents are archived before removal. A detached lease watcher handles extension-host exits that skip deactivation. Open documents and live leases protect active workspaces during startup cleanup. Uninstall preserves recovery and pending-work journals and waits for an active owner to release its workspace.

Recovery archives live below `globalStorage/pair-notebook.pair-notebook/recovery/temporary-sessions/`. Each `.jsonl.gz` contains a format header followed by records with `path` and base64 `content`. `workspace/` records preserve disk changes, `buffers/` records preserve unsaved editor contents, and sibling journal records preserve local operations. Extract into a separate empty directory; never automatically apply an archive to a new session or notebook epoch. Existing archives are retained deliberately.

The Pair kernel is disposed when no session remains, including pending selection callbacks. The interactive device picker excludes offline devices. The server retires departed devices after presence expires or Leave, preserving the VPS device and devices with accepted work. A reconnecting device must register and obtain sharing permissions again.

Server workspace storage reclaims unreferenced immutable blobs after each durable manifest publication. The executor removes working directories for explicitly released or superseded idle kernel generations, retaining execution receipts, package environments, active kernels and unreportable results. Persistent projects and recovery are intentional retained data, not temporary session caches. Leaving one client never deletes a persistent server project or interrupts another participant's accepted execution.

Validation: TypeScript compilation and scoped ESLint; 182 Linux server/storage/provider/synchronizer tests; 37 Windows lifecycle/storage/compute tests; 32 Linux agent tests passed with two container/GPU prerequisites skipped. Two tests ran in a real Windows VS Code Extension Host: native controller removal with stale ownership, and dirty notebook recovery followed by workspace removal. The provider/synchronizer checks cover the 0.6.14 Overwrite fix, notebook epochs and Public/Private isolation.

The native tests exercised VS Code APIs and real notebook models; they did not click every kernel picker UI item. A literal uninstall from an actively edited production window, two physical computers, a long soak and the full platform release matrix were not rerun. Native Windows agent tests are unsupported because protected execution runs in Linux/WSL; the agent suite was run there. No production VPS update or cleanup was performed. Install the VSIX on each participating computer. Server and VPS-executor fixes require a separate explicit server update using the matching installer.
